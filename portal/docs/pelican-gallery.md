## 账号切换

保留现有分组 / 检查 Key 配置，并校验 Key 有效且属于所选分组。通过 Core 官方管理员账号列表接口（group 参数）查询该分组的 OpenAI 账号，只保留 active、schedulable、支持所配置模型、未处于账号级冷却或自动到期暂停的 API Key / OAuth 账号。

每轮按账号 ID 排序并轮换起点，最多尝试 3 个不同账号。同一轮中失败账号不会再次使用，超时、HTTP / SSE 限流、连接错误、无有效作品都切换到下一账号。切换等待 2 / 4 秒，每次使用独立会话 ID。候选不足时直接结束本轮。

Core 的普通模型入口不提供可靠的指定账号排除接口，现有官方连通性测试也不可靠地转发自定义题目。因此复用 Portal 逐账号检查的连接适配逻辑：由服务端管理员 Key 调用官方单账号导出接口，凭据只留在内存中，随后直接请求所选上游。遵循该账号的模型映射、Responses / Chat Completions 模式及代理。不修改账号状态，不写入 Core，不通过 Core 普通推理入口计费或生成 Core usage 记录；成功作品归属直接保存到 Portal。上游正常产生推理用量。

这是一条独立的服务端定时检查能力。原人工账号检查仍使用调用者 JWT，权限拒绝不会回退为服务器管理员 Key。

## 超时与流式结果

每个账号的完整尝试（含读取连接配置）限时 6 分钟。3 次尝试共 18 分钟，总任务限时 19 分钟，Key 校验 15 秒、账号列表 30 秒，剩余时间覆盖换号等待和收尾。超过 20 分钟仍 running 的任务才回收；优雅关闭等待 20 分钟，容器停止宽限 21 分钟。

收到 SSE 完成 / 失败终止事件后立即关闭上游响应，不等待对方断开连接。流式 HTTP 200 中的 rate_limit_exceeded 同样判失败并换号。失败 / 未完整生成的 HTML 永不发布。

## 自定义检查配置

管理员可配置模型 ID（最多 200 字符）和检查题目（最多 10000 字符），不能为空。默认沿用 gpt-6-astra 和鹈鹕骑自行车题目。迁移 025 为旧配置补齐默认值。关闭检测时也可保存题目和模型。

立即检查会先保存未提交的配置；定时检查读取已保存配置。每轮开始时固定题目和模型，运行期间修改配置从下一轮生效。账号筛选使用配置的模型，输出仍要求自包含 HTML / SVG。自动刷新不会覆盖编辑中的题目和模型，普通用户不会收到自定义题目和模型字段。

模型下拉列表从所选 API Key 的 Core `/v1/models` 读取，保留已有模型值。思考深度可选 none、minimal、low、medium、high、xhigh；迁移 026 默认 high。上游对深度支持不同，较高深度可能耗时更久。
